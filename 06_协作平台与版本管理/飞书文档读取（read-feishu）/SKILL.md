# Read Feishu Skill

> **路径配置**：本文件中的 `{SKILLS_ROOT}` 占位符请从 `CONFIG.md`（skills 根目录）读取实际路径。

读取飞书文档的两种方式，按实际环境选择，并在读取后处理文档中可能内嵌的 PDF 文件。

## 适用场景

- 用户提供了飞书文档 URL，要求先读取文档内容。
- 用户要求把飞书需求"落地"再继续开发流程。
- 需要给后续技能（如 `ui-workflow`）提供可读输入材料。

---

## Step 0: 多文档预处理与方式选择

### 0.1 识别所有待读取文档

**首先统计用户提供的所有飞书文档 URL**，建立处理队列。

> ⚠️ **强制要求**：用户提供了几个 URL，Agent 就必须自己依次处理完全部，**绝不允许以"节省时间""让用户自己来"等任何理由跳过剩余文档**。所有文档由 Agent 独立完成，中间不需要用户介入（除非遇到登录问题）。

如果有多个文档，在开始前告知用户：
> 检测到 N 篇飞书文档，将依次读取：
> 1. `<URL1>`
> 2. `<URL2>`
> ...

### 0.2 选择读取方式

在执行前，**先检查可用工具再询问用户选择**（只需询问一次，后续所有文档使用相同方式）：

**MCP 工具可用性检查**：在列出选项前，**必须先确认自己当前是否拥有 `docx_v1_document_rawContent` 这个 MCP 工具**。如果没有该工具，则**不要列出方式 B**，直接只提供方式 A 并告知用户。

**两种方式都可用时**：
> 检测到两种可用的飞书文档读取方式，请选择：
>
> **A. 逐页截图**（`physical_screenshot.py`）
> - 适合：含图片、表格、复杂排版的文档
> - 产物：`screenshots/feishu_page_001.jpg` ~ `feishu_page_NNN.jpg`（每屏一张独立图片）
> - 要求：执行期间**不要操作鼠标和键盘**
>
> **B. MCP 纯文本**（`docx_v1_document_rawContent`）
> - 适合：以文字内容为主的文档，需要精确复制文字
> - 产物：原始文本内容（直接在对话中输出）
> - 要求：已配置飞书 MCP 服务器

**仅方式 A 可用时**：
> 当前环境未配置飞书 MCP 服务器（`docx_v1_document_rawContent` 不可用），将使用**逐页截图**方式读取。
> 执行期间**请勿操作鼠标和键盘**。

如果用户未明确说明，默认推荐 **A（截图）**。

## 方式 A：执行脚本截图

### 前置条件

1. 本机已安装 Chrome 或 Microsoft Edge 浏览器。
2. Python 环境可用，且已安装依赖：`Pillow`、`pyautogui`、`pygetwindow`。

> 安装依赖：
> ```powershell
> pip install pillow pyautogui pygetwindow
> ```

### Step A-0: 询问浏览器并检查登录状态

执行前**先询问用户使用哪个浏览器**（chrome / edge），然后运行登录检查脚本：

```powershell
cd {SKILLS_ROOT}\工具类\文档读取\read-feishu
python -u scripts/check_login.py <FEISHU_DOC_URL> <chrome|edge>
```

脚本会打开 URL、等待加载、截取一张截图保存为 `feishu_login_check.jpg`。

> **Agent 必须直接读取并查看该图片文件（请使用你标准的 `read_file` 工具或直接分析文件路径）。**
> 💡 **能力提醒**：你本身自带强大的原生视觉大模型能力（Vision），完全可以直接看懂图片内容！**切勿去寻找名为 "Read" 的特殊工具，也绝对不要以为自己无法处理图片。**
> 利用你的视觉能力观察该图片：
- ✅ 看到文档正文内容 → 已登录，进入 Step A-1
- ❌ 看到登录表单/二维码/空白页 → 告知用户需要登录，等待用户登录完成后**重新运行 check_login.py** 确认

> ⏸️ **强制挂起**：截图显示未登录时，必须等待用户确认已登录后再继续，不得跳过。

### Step A-1: 执行截图脚本

确认已登录后，提醒用户 **请勿操作鼠标和键盘**，然后执行：

```powershell
python -u scripts/physical_screenshot.py <FEISHU_DOC_URL> <chrome|edge> [click_x] [click_y]
```

**参数说明**：
| 参数 | 说明 | 默认值 |
|------|------|--------|
| `click_x` | 点击位置水平比例（0.0~1.0，占窗口宽度） | `0.6` |
| `click_y` | 点击位置垂直比例（0.0~1.0，占窗口高度） | `0.5` |

不同飞书文档页面布局不同，焦点需要落在可滚动的内容区域，PageDown 才能正常工作。常见参考值：
- 标准文档页面：`0.6 0.5`（默认，避开左侧目录栏）
- 有右侧面板的文档：`0.4 0.5`
- Wiki 知识库页面：`0.5 0.5`

首次执行使用默认值即可。

> 浏览器参数与 Step A-0 保持一致。
> ⚠️ **终端超时与日志截断处理规范（极其重要）**：
> 由于截图过程需要 30~60 秒，你的终端工具极有可能会**提前返回（Premature Return）**并截断日志（例如输出停在 `截取第 3 屏...` 就结束了）。
>
> **当你遇到这种情况时，请严格遵守以下纪律：**
> 1. **不要恐慌，不要判定失败**：这不代表脚本崩溃，脚本仍在操作系统的后台继续物理翻页。
> 2. **绝对禁止立即检查文件**：此时千万不要立刻使用 `dir` 去检查 screenshots 目录，因为截图还没完成！
> 3. **强制等待重试机制**：你必须执行睡眠命令等待 15 秒（例如执行：`python -c "import time; time.sleep(15)"`），然后再使用 `dir` 命令检查 screenshots 目录中的文件列表。
> 4. 如果 15 秒后目录中的文件还在增加（脚本仍在运行），请再次等待 15 秒后重试。直到确认脚本输出了 `[SUCCESS]` 或文件列表不再增加后，再开始逐页读取。

### Step A-2: 等待脚本完成

脚本运行期间会：

1. 用用户选择的浏览器打开目标 URL，等待约 8 秒页面加载。
2. 自动最大化并激活浏览器窗口。
3. 点击文档右侧空白区域获取焦点，避免误触文档内容。
4. 循环按 `PageDown` 滚动，每次截图并通过精确哈希判断是否到达底部。
5. 检测到画面不再变化时停止，最多滚动 30 屏。
6. **每屏保存为独立图片文件**，存放在 `screenshots/` 子目录下。

### Step A-3: 校验产物

- 期望输出目录：`{SKILLS_ROOT}\工具类\文档读取\read-feishu\screenshots\`
- 期望输出文件：`feishu_page_001.jpg`、`feishu_page_002.jpg`、...

### 成功标准

脚本输出包含：

```
[SUCCESS] 截图完成，共 N 页，保存在: ...screenshots
```

并且 `screenshots/` 目录下存在对应数量的 `feishu_page_XXX.jpg` 文件。

### Step A-4: 逐页阅读并理解截图内容（必须执行）

> 🔴 **截图完成后必须逐页阅读，不得仅汇报"截图已生成"就停止。**

**逐页读取流程**：
1. 使用 `Read` 工具（或 `read_file`）**按顺序逐张读取** `feishu_page_001.jpg`、`feishu_page_002.jpg`、...
2. 每张图片都是独立的一屏（约 1920×1080），文字清晰可读，利用视觉能力提取内容。
3. 将所有页面的内容汇总，整理为结构化摘要：
   - 文档的核心主题与目标
   - 关键功能点、交互逻辑、业务规则
   - 涉及的 UI 元素、状态、数据字段
   - 任何数值、枚举、配置要求
4. 输出结构化摘要给用户，让用户确认理解无误。

> ⚠️ **优雅回退**：如果读取图片时报错（二进制文件限制、无权限等），请告知用户：
> "截图已成功保存在 `screenshots/` 目录下，共 N 页。但由于环境限制我无法自动读取图片，请将 screenshots 目录中的图片拖拽到聊天窗口发给我。"
> **绝对禁止因此私自切换到方式 B (MCP)。**

### 失败与排查

#### 0) 截图只有 1 页（PageDown 未滚动）

可能原因：
- 焦点没有落在文档的可滚动内容区域内（被侧边栏、评论区、或页面外区域捕获）。

处理：
- **检查第 1 张截图**：读取 `feishu_page_001.jpg`，观察文档是否明显不止一页。
- **换点击位置重试**：使用不同的 `click_x` 参数重新执行脚本，按以下顺序尝试：
  1. `click_x=0.5`（居中）
  2. `click_x=0.4`（偏左）
  3. `click_x=0.7`（偏右）
- 示例：`python -u scripts/physical_screenshot.py <URL> chrome 0.5 0.5`
- 每次重试前脚本会自动清理旧截图，无需手动删除。

#### 1) `[ERROR] 找不到浏览器窗口！`

可能原因：
- 浏览器未成功启动，或窗口标题不含 `Edge`/`Chrome`。

处理：
- 确认所选浏览器已正确安装。

#### 2) `[ERROR] 未能截取到任何画面！`

可能原因：
- 截图前窗口被遮挡或最小化。
- 权限不足导致 `ImageGrab` 返回空白。

处理：
- 确保执行期间不操作其他窗口。
- 以管理员权限运行终端后重试。

#### 3) 截图内容异常（空白页面）

可能原因：
- 页面加载超时（网络慢时 8 秒不够）。

处理：
- 将脚本中 `time.sleep(8)` 适当调大（如改为 `12`）。

#### 4) `ModuleNotFoundError`

```powershell
pip install pillow pyautogui pygetwindow
```

## 方式 B：MCP 纯文本读取

### 前置条件

已配置飞书 MCP 服务器，且该服务器提供 `docx_v1_document_rawContent` 方法。

### Step B-1: 提取文档 Token

从飞书文档 URL 中提取 document token（URL 路径最后一段），例如：

```
https://herogames.feishu.cn/wiki/KXpuwRRJXiBYagkR3DdcfiLXnOg
                                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                    document_id = KXpuwRRJXiBYagkR3DdcfiLXnOg
```

### Step B-2: 调用 MCP 方法

调用 `docx_v1_document_rawContent`，传入提取的 `document_id`，获取文档的纯文本内容。

### Step B-3: 阅读并理解文本内容（必须执行）

> 🔴 **获取文本后必须立即理解，不得仅展示原始文本就停止。**

对获取到的文本内容进行深度阅读，提取并理解：
- 文档的核心主题与目标
- 关键功能点、交互逻辑、业务规则
- 涉及的 UI 元素、状态、数据字段
- 任何数值、枚举、配置要求

将理解结果整理为结构化摘要输出给用户，让用户确认理解无误。

---

## Step Final: 检查内嵌 PDF

无论使用哪种方式读取文档，读取完成后需检查文档中是否包含**内嵌的 PDF 文件**。

判断依据：
- 截图中出现 PDF 预览框、PDF 文件名、或 PDF 图标。
- 纯文本中出现 PDF 文件名或附件链接标注。

### 如果发现内嵌 PDF，执行以下流程：

1. **告知用户**检测到文档中包含 PDF 文件，列出发现的 PDF 名称或描述。
2. **询问用户**是否需要读取该 PDF 内容：

   > 文档中检测到内嵌 PDF：`<PDF 名称>`，是否需要读取其内容？
   > 如需读取，请在飞书中手动下载该 PDF 到本地，然后将本地路径告诉我。

3. **等待用户提供本地路径**，收到后使用 `Read` 工具读取该 PDF 文件。
4. 将 PDF 内容与飞书文档内容合并，作为完整的需求输入。

## Agent 执行约束

### 方式互斥与脚本白名单（关键）

> 🚫 **用户选定方式后，必须且只能使用该方式的流程完成读取，绝不允许切换到另一种方式或自行发明替代方案。**

- **本 Skill 最多两种读取方式**：方式 A（截图）和方式 B（MCP 纯文本）。方式 B 需确认 `docx_v1_document_rawContent` MCP 工具可用，不可用时只有方式 A。
- **方式 A 只使用以下两个脚本**，均位于 `{SKILLS_ROOT}\工具类\文档读取\read-feishu\scripts\` 目录下：
  - `check_login.py` —— 登录检查
  - `physical_screenshot.py` —— 逐页截图（每屏独立保存）
- **方式 B 只调用 MCP 方法** `docx_v1_document_rawContent`，不执行任何 Python 脚本。
- **禁止自创脚本或调用不存在的脚本**（如 `read_feishu_and_save.py`、`feishu_reader.py`、`screenshot.py` 等均不存在，不得尝试调用）。
- 如果所选方式失败，应按"失败与排查"章节修复后重试同一方式，或询问用户是否改用另一种方式，**而非自行编写新脚本**。

### 多文档处理约束（严格串行，禁止并发）

> 🚫 **多文档必须严格串行处理，绝对禁止任何形式的并发或"优化跳步"。**

**执行顺序强制规则**：
1. 完整处理第 1 个文档（含：截图/MCP → 阅读理解 → PDF 检查）后，才能开始第 2 个。
2. 在某个文档的处理过程中，**禁止同时对其他文档执行任何操作**，包括但不限于：
   - 禁止在等待截图脚本运行时，去调用 MCP 读取其他文档
   - 禁止以"节省时间""提前并行准备"等理由提前处理后续文档
3. 用户选择了方式 A，**所有文档都必须走方式 A 的完整流程**（check_login → physical_screenshot → 阅读截图），不得对某些文档改用方式 B 作为替代。
4. 用户给了几个 URL，Agent 就必须全部处理完，**不得跳过任何一个**，也不得要求用户自己处理剩余文档。
5. 每个文档处理完毕后，自动开始下一个，无需等待用户指令。仅在遇到**登录问题**时才暂停等待用户。
6. 所有文档处理完毕后，汇总所有文档的理解摘要一并呈现。

### 内容理解约束

- **截图/文本获取后必须立即阅读理解**，绝不允许仅告知"截图已生成"或"文本已获取"就停止。
- 理解输出必须是结构化摘要，而非原始内容的复述。

### 其他约束

- 必须使用用户提供的 URL，不得猜测或伪造链接。
- 执行方式 A 前提醒用户：**脚本运行期间请勿触碰鼠标和键盘**。
- 执行失败时，给出明确错误原因与下一步可执行修复动作，再决定是否重试。
