# SVN提交助手 (Commit Helper)

这个skill帮助你执行SVN提交，自动生成规范的提交信息。

## ⚠️ 重要：必须用户确认后才能提交

**在执行提交之前，必须完成以下步骤并获得用户确认：**

1. **获取修改内容**: 从对话历史中获取本次修改的文件列表
2. **Excel文件上锁**: 如果有 Excel 文件需要提交，必须先执行 `svn lock` 上锁
3. **展示diff**: 直接在会话中展示本次修改的 diff 内容
4. **添加/删除文件**: 用 `svn add` 添加新文件，用 `svn delete --keep-local` 标记删除文件
5. **获取TAPD信息并生成提交信息**: 询问用户 TAPD 标题和链接，生成规范的提交信息
6. **用户确认后执行**: 只有用户明确回复确认后，才执行 `svn commit` 命令（必须指定文件路径）

## ⚠️ Excel 文件上锁规则

**如果待提交文件中包含 Excel 文件（.xlsx），必须先上锁：**

```bash
svn lock [Excel文件路径] -m "提交需求锁定"
```

其他文件（.h, .cpp, .lua 等）**不需要上锁**。

## 提交信息格式

```
[TAPD标题]
[链接]

修改内容:
- [修改项1]
- [修改项2]
- ...

---
✨🌸 AI助手小薇协助提交 🔄🔷🌊
```

**注意：** 标题和链接需要从用户提供的信息中获取，链接直接跟在标题后面，不需要"TAPD链接:"这个前缀。

## 使用流程

### 步骤1: 获取本次需求的修改内容

**优先从对话历史中获取修改内容：**

- 基于本次对话中已完成的修改任务，整理修改的文件列表和修改详情

### 步骤2: Excel 文件上锁（如有）

如果待提交文件中包含 Excel 文件，先上锁：

```bash
svn lock [Excel文件路径] -m "提交需求锁定"
```

### 步骤3: 展示diff

**直接在会话中展示本次修改的 diff 内容，格式如下：**

对于修改的文件，使用 diff 格式展示：
```
@@ -行号,数量 +行号,数量 @@
-删除的行
+新增的行
```

对于新增的文件，展示完整文件内容。

对于删除的文件，说明已删除即可。

**不要使用** `svn diff` 命令，直接使用会话中已记录的修改信息。

### 步骤4: 添加新文件/文件夹和标记删除文件

**新增文件/文件夹：**
```bash
svn add [文件或文件夹路径]
```

添加文件夹时会自动包含其下的所有文件：
```bash
svn add "Source/EM/Public/Game/DungeonObject" --force
```

**删除文件/文件夹：**
本地删除的文件需要用 `svn delete` 标记：
```bash
svn delete [文件路径] --keep-local
```

`--keep-local` 参数表示保留本地文件（因为已经手动删除了），只在版本库中标记为删除。

**⚠️ 重要：** 
- 如果本地已删除文件但没有用 `svn delete` 标记，SVN 状态会显示 `!`，提交时不会包含这些删除操作
- 新增文件夹时，提交命令需要包含文件夹路径（会自动包含其下文件）

### 步骤5: 获取TAPD信息并生成提交信息

**⚠️ 重要：必须要有TAPD标题和链接才能提交。**

**先询问用户TAPD标题和链接：**
```
请提供本次提交的 TAPD 标题和链接？
```

**用户必须提供标题和链接**，格式通常是：
```
【标题】
https://www.tapd.cn/xxx
```

获取到TAPD信息后，生成提交信息并向用户展示：

```
以下是将要提交的内容：

【修改的文件】
- 文件1
- 文件2

【提交信息】
[TAPD标题]
[链接]

修改内容:
- 修改项1
- 修改项2

---
✨🌸 AI助手小薇协助提交 🔄🔷🌊

请确认是否提交？(确认/取消)
```

### 步骤6: 用户确认后执行提交

只有用户明确回复"确认"、"是"、"OK"等肯定答复后，才执行。

**⚠️ 重要：必须只提交本次修改的文件，在 svn commit 命令中明确指定文件路径：**

```bash
svn commit [文件路径1] [文件路径2] ... -m "[提交信息]"
```

**⚠️ 注意：** 必须指定文件路径，不要使用不带文件路径的命令，否则会提交工作区所有已暂存的修改。

## 常用SVN命令

| 命令                | 说明                    |
| ----------------- | --------------------- |
| `svn status`      | 查看文件状态                |
| `svn status -u`   | 检查是否有更新（显示 `*` 表示有更新） |
| `svn diff`        | 查看修改内容                |
| `svn log -l 5`    | 查看最近5条提交记录            |
| `svn update`      | 更新代码                  |
| `svn revert [文件]` | 撤销修改                  |
| `svn add [文件]`    | 添加新文件                 |

## 注意事项

- 提交信息要清晰描述修改内容
- 每次提交尽量保持单一目的，便于回滚
- 检查是否误添加了不该提交的文件（如临时文件、配置文件等）
- **严禁未经用户确认就执行提交命令**

## 经验总结

### 不需要提交的文件
- 以 `.` 开头的隐藏文件夹（如 `.trae`、`.XXX` 等）中的文件不属于业务代码，不应提交

### 获取修改文件列表
- **不要执行 `svn status`**，直接从对话历史中获取本次修改的文件列表
- 这样可以避免提交不相关的文件

### PowerShell 提交命令
- 使用 PowerShell 直接执行 `svn commit` 命令
- 多行提交信息在 PowerShell 中会自动处理（命令行会进入多行输入模式 `>>`）
- emoji 签名可以正常提交
