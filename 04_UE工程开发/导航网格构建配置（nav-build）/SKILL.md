## Prerequisite Rules (MUST Follow)

### 1. Level Naming Convention

| Type | Suffix | Description |
|------|--------|-------------|
| Navigation main level | `_NavMesh` | Editable navigation range level |
| Navigation sub-level | `_NavMesh_XXXXX` | 5-digit suffix, auto-generated by division tool, **do not edit unless necessary** |

### 2. NavRecast MUST be in PersistentLevel

- NavRecast is auto-generated by engine, runtime nav culling and queries depend on it
- Must be in **PersistentLevel**, unaffected by sub-level load/unload
- Main level needs **3 EMRecast** instances (auto-generated: drag NavMeshVolume into main level -> BuildPath)

### 3. At Least One MainPoly (BP_MainPolyActor)

- Nav culling system uses `BP_MainPolyActor` to determine nav validity
- All nav polys not connected to any MainPoly will be culled
- If areas are incorrectly culled, place a MainPoly or use jump links to connect

## Navigation Build Flow (New Modifier-based Culling)

### Flow Chart

```
Step 1: Load Art level + Nav level
Step 2: Check Recast's IsCullIsolatedPolys is checked (default on, do NOT uncheck)
Step 3: Check bCullIsolatedPolysByNavModifier (only when regenerating Modifier)
Step 4: Build Paths (engine auto-completes two builds)
Step 5: Verify culling result
Step 6: Save navigation levels
```

### Step Details

**Step 3 - bCullIsolatedPolysByNavModifier (KEY)**

Only check this when you need to **regenerate all Modifiers**. When checked:
- Auto deletes all old `AEMNavModifierVolume` in scene
- After first build completes, engine auto-calculates culled areas and generates new `AEMNavModifierVolume`
- `bCullIsolatedPolysByNavModifier` auto-unchecks after first build
- Engine auto-triggers second build via `EnsureBuildCompletion()` (see code: `EMRecastNavMesh.cpp:367-383`)

**Do NOT check this when:**
- Only rebuilding navigation without Modifier changes
- Manually adjusting individual Modifiers

**Step 4 - Auto Second Build**

Code path in `EnsureBuildCompletion()`:
```cpp
// EMRecastNavMesh.cpp:367-383
if (FirstBuildCullPolyData.Num() > 0 && AgentRadius < 41.f)
{
    auto V1 = FNavigationSystem::GetCurrent<UNavigationSystemV1>(World);
    if (V1 && !V1->IsNavigationBuildInProgress())
    {
        if (FirstBuildCullPolyData.Num() > 0 && AgentRadius < 41.f && !bCullIsolatedPolysByNavModifier)
        {
            V1->Build();  // Auto second build
        }
    }
}
```

Full call chain:
```
Build Paths
  -> RebuildAll() [RebuildPathState = InFirstRebuild, delete old EMNavModifierVolume]
  -> Super::RebuildAll() starts build
    -> Build complete -> EnsureBuildCompletion()
      -> OnNavMeshGenerationFinished()
        -> CullIsolatedPolys() [calculate cull areas, spawn EMNavModifierVolume, fill FirstBuildCullPolyData]
        -> bCullIsolatedPolysByNavModifier = false
      -> FirstBuildCullPolyData.Num() > 0 -> V1->Build() [AUTO second build]
        -> RebuildAll() [RebuildPathState = InSecondRebuild, bCullIsolatedPolysByNavModifier=false, keep Modifiers]
        -> Build complete -> EnsureBuildCompletion()
          -> OnNavMeshGenerationFinished()
            -> RemergeMergeConsecutiveModifiers() [re-merge and optimize Modifiers]
            -> FirstBuildCullPolyData.Empty()
          -> FirstBuildCullPolyData.Num() == 0 -> RebuildPathState = Finished
```

## Navigation Division Flow

### One-Click Division (Recommended)

Execute first 4 steps of manual division -> confirm correct -> click one-click division -> save level.

### Manual Division Steps

| Step | Operation | Required |
|------|-----------|----------|
| 1 | Drag NavMeshVolume into main level -> BuildPath -> auto-generate 3 EMRecast -> save main level | YES |
| 2 | Load Nav sub-levels + Art levels (NOT previously divided sub-levels) | YES |
| 3 | Place MainPoly in Nav level, check IsCullIsolatedPolys, save main level | YES |
| 4 | Ensure only the Nav levels to be divided are loaded | YES |
| 5 | Open level tool -> nav block size default 4800 -> click nav divide | YES |
| 6 | Invalid nav culling (optional checkbox + button) | Optional |
| 7 | Store nav files -> save -> refresh Levels -> batch unload/reload new sub-levels -> right-click save | YES |
| 8 | Re-Build Path -> confirm AllBuildPolyRefs has values -> save | YES |

### Division Notes

- Original NavMesh replaced by **EMNavMesh** (with `IsMainNavMeshBoundsVolume` property, range-only marker)
- To adjust EMNavMesh area: uncheck `IsMainNavMeshBoundsVolume` -> Build Paths to preview -> **MUST re-check after adjustment**
- NavMesh count over **300** may cause freeze during storage
- Large maps: divide by region separately

## Incremental EMNavModifier Generation

Two entry points for incrementally generating EMNavModifier without full rebuild.

### Entry 1: CreateNavModifierIncrement() - Single Level Manual

**Code**: `EMRecastNavMesh.cpp:1780`
**Usage**: Select EMRecastNavMesh in editor -> Details panel -> EM category -> click `Create Nav Modifier Increment`

**Logic**:
1. Scan all nav mesh Tiles/Polys
2. Find Polys with `Poly->getArea() == RECAST_NULL_AREA` (already culled)
3. Collect vertices -> calculate bounding boxes
4. MergeCullPolysData() + TryMergeConsecutiveModifiers() + RemoveOverlap() for optimization
5. Generate AEMNavModifierVolume for each merged OBB
6. Place in `/IncrementModifier` folder
7. Z-axis extra expansion: +30/-30 units

**Key traits**:
- Does NOT delete existing EMNavModifierVolume
- Does NOT trigger Build Paths
- Has merge optimization

**Use case**: Local terrain adjustment caused new isolated nav areas that need Modifier coverage, but full rebuild is unnecessary.

### Entry 2: IncrementNOWCNavModifiers() - Batch Level Auto

**Code**: `WCEditFunctionLibrary.cpp:11233`
**Usage**: Call from editor tool/blueprint with level path array

**Logic**:
1. Load level
2. Find Recast with AgentRadius < 45 (3rd nav layer)
3. Rebuild nav once (bCullIsolatedPolysByNavModifier = false, no Modifier regen)
4. Scan for `RECAST_NULL_AREA` Polys
5. Generate EMNavModifierVolume per Poly (no merge optimization)
6. If new Modifiers spawned -> Build again to apply
7. Save level
8. Recursive check up to 3 times (DeepCheckCount) if new Modifiers were generated
9. Process next level

**Key traits**:
- Rebuilds nav first, then scans NULL_AREA Polys
- No merge optimization (generates per-Poly Modifiers)
- Auto-rebuilds after generating Modifiers
- Recursive verification (max 3 iterations)
- Batch processes multiple levels

**Use case**: Batch updating nav Modifiers for multiple levels, especially NOWC (non-open-world) levels. Auto-called after `RebuildLevelsPaths` as supplementary check.

### Full Build vs Incremental Comparison

| | Full Build (bCullIsolatedPolysByNavModifier) | Incremental |
|---|---|---|
| Trigger | Check Recast property -> Build Paths | CreateNavModifierIncrement or IncrementNOWCNavModifiers |
| Delete old Modifier | YES | NO |
| Rebuild nav | YES (auto twice) | CreateNavModifierIncrement: NO; IncrementNOWCNavModifiers: YES once |
| Culling method | MainPoly connectivity check | Scan RECAST_NULL_AREA Polys |
| Merge optimization | YES | CreateNavModifierIncrement: YES; IncrementNOWCNavModifiers: NO |
| Use case | Large-scale nav rebuild | Local supplement / batch level patching |
| Time cost | Long (two full builds) | Short (no build or one build) |

## EMNavModifierVolume vs Native NavModifierVolume

| | EMNavModifierVolume | NavModifierVolume (Native) |
|---|---|---|
| Prefix | EM | None |
| Function | Same as native | Native |
| On full rebuild | Auto deleted and regenerated | Unaffected |
| Purpose | Marks auto-generated cull areas | Manually placed modification areas |
| Conversion | `TransToNormalModifier()` one-click to native | - |

When a specific EMNavModifierVolume has precision issues, use `TransToNormalModifier()` to convert it to native. This way it won't be affected by future full rebuilds.

## Quick Reference by Scenario

### Scenario A: New Level First-Time Nav Setup
```
1. Drag NavMeshVolume into main level -> BuildPath -> generate 3 EMRecast -> save
2. Load Art + Nav levels
3. Place MainPoly (ensure connectivity)
4. Check IsCullIsolatedPolys + bCullIsolatedPolysByNavModifier
5. Build Paths (engine auto-completes two builds)
6. Verify culling result
7. Save all levels
```

### Scenario B: Rebuild Nav Only (Modifiers Unchanged)
```
1. Build Paths -> save levels
(Do NOT check bCullIsolatedPolysByNavModifier)
```

### Scenario C: Local Modifier Adjustment
```
1. Manually add/remove specific Modifiers (no full regen needed)
2. Build Paths -> save levels
```

### Scenario D: Local Terrain Change - Supplement Modifier
```
1. Modify terrain/collision in an area
2. Build Paths -> find area culled but no Modifier
3. Select EMRecastNavMesh -> click CreateNavModifierIncrement
4. Incremental generate missing Modifiers -> Build Paths -> save
```

### Scenario E: Batch Level Nav Update
```
1. Use RebuildLevelsPaths for batch rebuild
2. Auto-calls IncrementNOWCNavModifiersImp for incremental check
3. Auto recursive check (max 3 times)
4. Auto save
```

### Scenario F: Precision Issue Fix
```
1. Find problematic EMNavModifierVolume
2. Adjust Z-axis size, or click TransToNormalModifier() to convert to native
3. Build Paths -> save levels
```

## Important Notes

1. **IsMainNavMeshBoundsVolume**: When adjusting EMNavMesh area, uncheck this to let it participate in Build Paths. MUST re-check after adjustment, otherwise division and build results will be affected.
2. **AllBuildPolyRefs**: If doing full nav data reconstruction, clear this property on all 3 Recasts first.
3. **Large maps**: Divide by region, don't load all NavMesh levels at once. NavMesh count > 300 may freeze during storage.
4. **Runtime culling disabled**: With Modifier-based culling, runtime dynamic culling is disabled (`IsDisableRuntimeCullIsolatedPolys`). Editor and runtime nav data are identical (WYSIWYG).
5. **AgentRadius < 41.f**: Modifier-based culling only applies to the first nav layer (AgentRadius < 41.f). Other layers are unaffected.
6. **NavModifierMinHalfZ**: Default 30.f. Controls minimum Z half-height of generated Modifiers. Adjustable via Recast property.
7. **NavModiferCreateTolerance**: Default 0.f. Extra Z-axis tolerance for generated Modifiers. Adjustable via Recast property.
