# Workflow Reviewer

工作流审查原子能力,提供架构审查和执行审计功能。

## 能力定位

- **架构层级**: 能力层(原子能力)
- **调用方**: 工作流标准步骤(如"验证目录结构"、"执行质量验证")
- **核心职责**: 审查工作流架构合规性、监控执行质量

## 标准接口

### 输入

```yaml
workflow_path: 工作流路径(如 .worker/.wiki/工作流/性能与稳定性/)
review_mode: 审查模式(architecture|execution|both)
execution_log: 执行日志路径(execution模式时必需,如 .worker/running/logs/execution_<timestamp>.log)
```

### 输出

```yaml
review_report_path: 审查报告路径(.worker/running/reports/review/<workflow_name>_<timestamp>.md)
compliance_score: 合规性评分(0-100)
issues_found: 发现的问题数量
recommendations: 改进建议列表
```

### 执行契约

```text
输入: workflow_path, review_mode, execution_log(可选)
  ↓
读取工作流目录结构
  ↓
架构审查(architecture/both模式)
  ├─ 目录结构审查
  ├─ 文件命名审查
  ├─ 步骤纯粹性审查
  └─ 知识归位审查
  ↓
执行审计(execution/both模式,需execution_log)
  ├─ Token经济检查
  ├─ 步骤冗余检查
  ├─ 信息混淆检查
  ├─ 设计合理性检查
  └─ 执行一致性检查
  ↓
生成审查报告
  ↓
输出: review_report_path, compliance_score, issues_found, recommendations
```

## 审查维度

### 一、架构审查(architecture模式)

对工作流执行架构层面的合规性检查:

#### 1. 目录结构审查

| 检查项 | 合规标准 | 不合规示例 |
|--------|---------|-----------|
| 必需目录 | 存在 `00_共享库/`、`_INDEX.md` | 缺少共享库或索引文件 |
| 层级深度 | 专项知识库 ≤ 5 层 | `A/B/C/D/E/F.md` |
| 文件命名 | `<类别名>_<内容>.md` 格式 | `common.md`、`踩坑经验.md` |
| 禁止项 | 无 `common/`、`problems/` 等通用词目录 | 存在 `common/` 目录 |

**层级计算规则**:
- **专项知识库**: 从专项知识目录开始计算(如 `性能与稳定性/00_共享库/专项知识/01_分析核心/` → 4层)
- **主知识库**: 从 `.wiki/` 开始计算(如 `.wiki/知识/` → 2层)

#### 2. 文件命名审查

| 检查项 | 合规标准 | 不合规示例 |
|--------|---------|-----------|
| 知识文档 | `<类别名>_<内容>.md` 格式 | `踩坑经验.md` |
| 步骤文档 | `<动词>_<对象>.md` 格式 | `step1.md` |
| 工作流文档 | `WORKFLOW.md` | `workflow.md` |

#### 3. 步骤纯粹性审查

| 检查项 | 合规标准 | 不合规示例 |
|--------|---------|-----------|
| 契约定义 | 只包含目标、输入输出、依赖、唤醒技能 | 包含详细执行逻辑 |
| 状态转移 | 定义 `exit_condition`,不定义 `outputs`(物理操作步骤除外) | 中间步骤定义文件输出 |
| 避免越权 | 不写"如何解析"、"如何重试"等执行细节 | 包含"脑内自愈准则" |

#### 4. 知识归位审查

| 检查项 | 合规标准 | 不合规示例 |
|--------|---------|-----------|
| 步骤与知识分离 | 步骤只留契约,执行逻辑在技能或补丁库 | 步骤包含"如何执行" |
| 技能与业务分离 | 通用执行逻辑在技能,业务逻辑在补丁库 | 通用逻辑混入补丁库 |

### 二、执行审计(execution模式)

对工作流执行过程进行5个维度的质量检查(需要执行日志):

#### 1. Token 经济

| 检查内容 | 判定标准 |
|---------|---------|
| 执行过程中读取的文件是否合理 | 是否读取了不必要的文件/重复读取/解析了大段无关内容 |

#### 2. 步骤冗余

| 检查内容 | 判定标准 |
|---------|---------|
| 执行的步骤是否可以被替代或合并 | 是否存在"为了存在而存在"的步骤/上游已完成同样工作 |

#### 3. 信息混淆

| 检查内容 | 判定标准 |
|---------|---------|
| 步骤描述是否清晰可执行 | 是否出现"这文件到底让我读哪个"的停顿或错误理解 |

#### 4. 设计合理性

| 检查内容 | 判定标准 |
|---------|---------|
| 步骤在工作流中是否有必要 | 删掉它整个工作流仍能跑/与下游需求错位 |

#### 5. 执行一致性

| 检查内容 | 判定标准 |
|---------|---------|
| 是否按预想执行 | 是否出现违反声明的约束/跳过声明的必做项 |

## 使用方法

本技能是原子能力,由工作流标准步骤调用:

### 工作流中调用示例

```markdown
# 验证目录结构

## 技能依赖
- workflow_reviewer

## 执行步骤
1. 确定审查范围(单个工作流或整个类别)
2. 调用 workflow_reviewer 执行架构审查
3. 审阅审查报告
4. 决定是否需要重构
```

```markdown
# 执行质量验证

## 技能依赖
- workflow_reviewer

## 执行步骤
1. 收集工作流执行日志
2. 调用 workflow_reviewer 执行执行审计
3. 审阅审计报告
4. 决定是否需要迭代优化
```

### 直接调用(调试用途)

```text
审查工作流架构:
- 工作流路径: .worker/.wiki/工作流/性能与稳定性/
- 审查模式: architecture

审查工作流执行质量:
- 工作流路径: .worker/.wiki/工作流/性能与稳定性/
- 审查模式: execution
- 执行日志: .worker/running/logs/execution_20260714.log
```

## 注意事项

1. **架构优先**: 先审查架构层面的错误(目录结构、步骤纯粹性),再检查物理错误
2. **智能判断**: 使用大模型推理能力,理解文档语义,识别架构层面的越权和错误
3. **量化优先**: 执行审计时尽量提供量化数据(Token消耗、步骤数量等)
4. **可操作建议**: 改进建议必须具体可执行,避免模糊表述
